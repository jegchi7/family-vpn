# ADR-0025 · Закрытый RU ingress и network stand

Дата: 08.10.2026. Статус: локальная реализация operator tools; native Linux/client/production acceptance открыты.

Владелец запросил actual RU ingress и network isolation до первого Android подключения через два сервера. Выбран ограниченный IPv4 primary slice: RU Xray26.3.27 VLESS/TCP443/REALITY → loopback SOCKS1080 sing-box1.14.2 → exact private Foreign VLESS hop. Namespace фиксирован как `vpn-data`, veth `fvpn-host`/`fvpn-ns`; private RFC1918 `/30`, uplink и оба public IPv4 выбираются независимо. Нет RU DIRECT fallback, AWG/TUN/backup пока вне этого runtime среза.

В pinned Xray `GetREALITYConfig` использует отдельный обычный `net.Dialer.DialContext`; listener не переопределяет его через `sockopt.dialerProxy`. Camouflage target поэтому фиксирован как `127.0.0.1:10443`; отдельный sing-box raw TCP direct **inbound** переадресует только выбранному public TLS IPv4:443 через единственный Foreign outbound. Этот тип inbound не добавляет DIRECT egress. Primary sources: [REALITY config](https://github.com/XTLS/Xray-core/blob/v26.3.27/transport/internet/reality/config.go), [TCP listener](https://github.com/XTLS/Xray-core/blob/v26.3.27/transport/internet/tcp/hub.go), [direct inbound](https://github.com/SagerNet/sing-box/blob/v1.14.2/protocol/direct/inbound.go).

RU staging root-only/fixed/private/no-overwrite, closed canonical schema; начальные clients пусты. Новая identity неизвестного владельца не создаётся. Pure binding существующих validated client bytes сверяет endpoint/SNI/derived public key/short ID, но требует отдельного trusted vault/current profile writer context. Нет plaintext URI выдачи, dump, manual ready или обхода ImportClientProfile/DEV-08/PRE-04. Configuration/client binding не client proof.

Исходная Foreign pair сохраняет exact v0.26 bytes. Новый private IPv4 execution adapter после ValidatePair меняет только DNS `UseIPv4` и freedom `ForceIPv4`, отвергает IPv6 endpoint/source/camouflage и не меняет credentials/peer/denies. Protected reader возвращает private bytes только trusted network stager; public/admin HTTP не получают stage/key/control/network доступ.

Pure netguard plan ограничивает RU external traffic только Foreign IPv4 TCP443; IPv4 loopback для SOCKS/relay разрешён внутри namespace, IPv6/DNS/external UDP/direct camouflage на RU запрещены. Foreign public TCP/UDP egress отделён от management/private/metadata/current host addresses. Host guard проверяет actual и original tuples через DNAT/SNAT, без blanket established namespace accept и без flush unrelated ruleset.

Native operator boundary требует independently expected current host boot/netns и SHA256 fixed protected ip/nft/sysctl/tc helpers, bounded inventory, fresh config binding и exact nft/topology/sysctl/policy-route/TC readback до activation. Legacy iptables, неподдержанные TC/XDP/packet rewrites/flow offload/policy routes и `/etc/netns/vpn-data` overrides блокируются. Prepared files/helper exit/synthetic proof не являются kernel acceptance. Proof TTL10s остаётся в private trusted memory с held namespace descriptor; он не profile lease/permission/readiness. `kernel_guard_verified` — current source-specific readback subset, а native/client/ready acceptance остаются false.

Helper execution входит в held namespace через отдельный locked thread, проверяет scope и восстанавливает independently expected host before releasing thread; failed restoration прекращает child group и удаляет contaminated thread. Host veth move использует inherited namespace FD, не named lookup. Guard повторяется перед каждым UP; default route добавляется после UP и проверяется final strict topology. Эта boundary локально скомпилирована/проверена synthetic tests; actual Linux setns/kernel execution ещё открыта. Короткий proof не lease: будущий core launcher обязан повторить guards.

Host forwarding0 блокируется до mutation: all/default/interface sysctl и NIC LRO preservation ещё не реализованы. Exclusive bounded private apply journal связан с manifest, сохраняется при ошибке и не допускает auto-resume. Повтор accepted только при complete journal плюс fresh full readback. Partial failure требует checked recovery; чужие network objects не удаляются и persisted stage не replay-ится как installed evidence. VPN cores/services не активируются этим срезом. Дальше dedicated unprivileged runtime/boot order, vault-bound client issuance, actual Ubuntu20.04 two-server tests, Android DNS/TCP/UDP/Foreign-loss/management/resource acceptance и audited state transition. Windows parser checks и cross-built artifacts эти требования не закрывают.

Operator workflow: [network-stand-runbook](../network-stand-runbook.md). Normative backlog/M1/G1 и original63 criteria сохраняются; никакой local fake/parser/staging result не делает production ready.
