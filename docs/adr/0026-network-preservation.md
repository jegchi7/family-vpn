# ADR-0026 · Forwarding preservation и закрытый Foreign Docker subset

Дата: 09.10.2026. Статус: локальная реализация v0.29; actual Linux network/management/client acceptance открыта.

Владелец подготовил RU/Foreign private primary configurations и сообщил различающийся network baseline: RU global forwarding0; Foreign forwarding1, existing Docker/Amnezia UDP30759, private docker0/amn0 bridges. Требуется продолжить network isolation, сохранив управление и existing AWG. Эти operator observations задают задачи реализации, а не native attestation. Из локальной разработки VPS/firewall/routes/SSH/Docker не изменяются.

Global forwarding0 нельзя безопасно исправлять одиночным sysctl: Linux `inet_forward_change` меняет default/per-interface forwarding и all.accept_redirects, вызывает пересчёт LRO/features. Выбрана ограниченная memory-only preservation procedure для reviewed devconf/feature subset. Она повторяет independently scoped complete observation, не принимает input snapshot и удерживает procfs file/ancestor descriptors до записи. Исходный non-loopback forwarding должен быть0; requested/active LRO должен быть0 на всех интерфейсах; pending mutable feature differences запрещены. Unsupported layout/driver/key, identity drift или unexpected дополнительное изменение дают blocker вместо произвольного restore.

Owned host+namespace nft guard устанавливается прежде сетевой activation; baseline0 host guard сохраняет unrelated forwarding DROP. Глобальный переключатель/all.forwarding становятся1; uplink и owned veth намеренно получают forwarding1 для data пути. Default.forwarding, all.accept_redirects и forwarding остальных исходных интерфейсов восстанавливаются из актуальной trusted memory, с exact before/after checks и guard перед каждой записью. Все другие reviewed devconf/features должны остаться равными baseline. Router semantics выбранного uplink и реальное сохранение management этим локальным тестированием не принимаются.

Canonical manifestformat2 содержит source/expected behavior fingerprints и closed coexistence metadata. Эти metadata и journal не содержат raw baseline/rule snapshot/feature vector/secret/восстановительных команд; existing private Foreign core config хранится отдельно в protected stage, как в v0.28. Persistence digest — конфигурационный fence, не restoration capability. Capture не восстанавливается после restart; cancelled/failed partial operation сохраняет protection+exclusive journal и требует независимой recovery проверки. Ни inverse toggle, ни auto-replay/resume, ни переход ready не добавляются.

Feature reader использует три закрытых GET ethtool UAPI commands, с bounds и проверкой independently expected scope до/после вызова. Произвольный command/pointer, driver SET и ethtool executable не принимаются. Generic kernel path допускает driver `begin`/`complete` callbacks; hard cancellation зависшего ioctl или отсутствие всех driver effects не заявляются. Driver/GET error blocks before writes. Linux5.4/5.15 source review и Linux amd64/arm64 cross-build не заменяют реальную проверку hardware/native boundary.

Whole-ruleset prohibition сохраняется на RU. Foreign получает narrow exception по actual bridge/address/routing inventories: private docker0/amn0 CIDR не пересекаются с independently selected namespace `/30`; NAT source positive bridge/local conditions и UDP30759 DNAT через LOCAL-destination entry graph отделены от owned namespace egress/TCP443 ingress. Fixed pinned `/usr/sbin/xtables-legacy-multi` optional SHA обязателен при наличии legacy tables; обе legacy семьи читаются отдельно от полного nft ruleset. Alternatives/default backend не выбираются. Fixed `-M /proc/0/exe` запрещает configured modprobe; legacy mutations используют bounded `-w 2`. Primary source: [iptables1.8.4 archive](https://www.netfilter.org/pub/iptables/iptables-1.8.4.tar.bz2), `xtables-legacy-multi.c`, `xshared.c`, `iptables-save.c`, `iptables.c`, `libxtables/xtables.c`. Docker recipe source: [Moby bridge setup](https://github.com/moby/libnetwork/blob/master/drivers/bridge/setup_ip_tables.go), [port mapping/entry jumps](https://github.com/moby/libnetwork/blob/master/iptables/iptables.go). Source review не является запуском этих tools или native acceptance.

Unmodified Docker FORWARD default DROP блокирует новый data путь даже после отдельного nft ACCEPT. Выбраны ровно два owned leading ACCEPT в shared standard IPv4 filter/FORWARD, ограниченные iif/oif `fvpn-host`. Они ставятся только после обоих independently owned guards и до UP; existing Docker entries/policy не удаляются, не переписываются и не flush-ятся. Independent nft forward guard позже проверяет data tuples и final drops. Shared head exact readback + original full semantic digest обязательны перед activation и при повторной native проверке. Неизменность Docker ruleset нормализует только transient counters/validated handles/metainfo; named identities, order и все другие predicates/policies сохраняются.

Namespace IPv6 запрещён; opaque xt statements, IPv6 NAT, unknown/protocol/port/bridge recipes, marks/CT assigns/offload/queue остаются blocker. Existing AWG service/peer proof не присваивается нашим profile/readiness states. Fixed helper/config parser, fake rule comparator, successful static build или staged manifest не подтверждают installed/core/client/native readiness. Actual Ubuntu20.04 both-backend packet, partial failure, boot/restart, existing AWG/management и Android acceptance остаются в NET/QA/M1/G1 backlog.

Operator contract: [network-stand-runbook](../network-stand-runbook.md). Исторический [ADR-0025](0025-network-stand.md) фиксирует v0.28; новый контракт дополняет его и не отменяет original63 criteria.
