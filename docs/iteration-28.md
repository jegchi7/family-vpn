# Итерация 28 · v0.28.0 · 08.10.2026

## RU ingress и закрытый IPv4 сетевой стенд

По прямому запросу владельца подготовка deployment guide заменена реализацией RU ingress и сетевой изоляции для первого VLESS/REALITY маршрута Android → RU → Foreign. Это локальная разработка operator tools. К VPS задача не подключалась; реальные firewall/routes/SSH/services, публичный кабинет и GitHub/Linear не изменялись. Полная network/client acceptance не заявлена.

`internal/rusetup` готовит новую private RU конфигурацию Xray TCP443 REALITY → loopback SOCKS1080 sing-box → exact Foreign primary VLESS. REALITY camouflage target Xray закреплён на loopback10443: отдельный sing-box TCP inbound направляет его к independently selected public TLS target через тот же Foreign outbound. DIRECT outbound/fallback отсутствует. Это требуется, потому что inspected pinned Xray REALITY camouflage использует plain dialer и не получает маршрут через обычный outbound selector автоматически. Local parser validation не проверяет TLS target, transport или сеть.

Initial ingress содержит пустой список clients: общей не привязанной к устройству учётной записи нет. Pure `BindValidatedClient` принимает только ограниченный validated VLESS URI и сопоставляет endpoint/SNI/derived server public key/short ID; возвращает новый private bundle, не выдаёт URI, не обходит ImportClientProfile или vault/current owner/device/generation/revision guards. Trusted writer-fenced issuance, unprivileged core runtime, actual peer/client proof и profile ready/download остаются отдельными незавершёнными границами.

Fixed RU staging/import paths защищены root ownership, directory0700/file0600, descriptor walk, no symlink/hardlink/special files, bounded closed JSON, exact regenerated bytes и atomic no-overwrite publication. Native syntax-only checks открывают только закреплённые cores/config descriptors, suppress output и не запускают listeners. Foreign `NamespaceIPv4Config` создаёт новую private UseIPv4/ForceIPv4 конфигурацию после strict original pair validation; original Foreign export bytes/credentials/peer/deny rules сохраняются, IPv6 input этого стенда запрещён.

`internal/netguard` компилирует closed explicit topology: RU/Foreign public IPv4, role-bound host public address/uplink и independently selected nonoverlapping RFC1918 /30, namespace `vpn-data`, fixed veth names. Host input от VPN veth закрыт; SNAT/DNAT scoped, public TCP443 Foreign ограничен RU source. Host rules проверяют actual и conntrack original source/destination/protocol/port на нескольких hooks; blanket established/related accept отсутствует. RU выпускает только exact Foreign TCP443, local RU SOCKS/relay и bounded legitimate replies/PMTU. Direct DNS/UDP/HTTPS/IPv6 запрещены. Foreign egress блокирует private/reserved/metadata/current local и public management addresses обоих серверов, включая original/current tuples после NAT. IPv6 блокируется на сервере, но client IPv6 full-tunnel/no-leak этим не подтверждается.

`VerifyNFTReadback` — bounded duplicate/depth-limited semantic comparator freshly obtained nft JSON с closed generated model: exact owned table/set/chain hooks/priorities/policies, ordered rules/expressions, IPv4 set contents. Только positive numeric handles и известные equivalent enum/prefix representations нормализуются; unknown/extra/missing/changed owned objects отклоняются. Namespace запрещает любые посторонние tables. Comparator не удостоверяет source сам: native caller обязан independently bind helper/scope, читать actual kernel и повторять guards. Strict unowned host rewrite gate оставляет обычные filter firewalls и отклоняет неподдерживаемые NAT, assignments, conntrack overrides, offload и неизвестные statements.

`internal/netstand` и `network-*` CLI отделены от public/admin HTTP, portal/control DB и agent socket. Применение требует independent current host boot/netns/topology и fixed protected helper hashes, свежий live inventory и current protected RU/Foreign config binding. Prepared artifact и успешный exit nft не являются kernel proof. Existing namespaces/veth/ports/routes/rewrites конфликтуют до изменения сети. Kernel readback выполняется перед каждым link UP; default route добавляется после UP, затем проверяется полный topology. Helper входит в удерживаемый namespace через `setns` на отдельном locked OS thread и восстанавливает expected host scope; при неудаче child group прекращается, thread не возвращается в pool. Host veth move использует тот же inherited FD, не повторный lookup по имени. TC/XDP/PBR, точные namespace addresses/routes и all/default/lo/veth sysctl проверяются вместе с nft. Private append-only operation journal — crash/retry fence, не permission/proof; partial/failed/ambiguous journal не позволяет blind resume и не удаляет установленные guards. Private TTL10s proof не восстанавливается из JSON и не является guard lease; будущий launcher обязан повторить актуальные guards.

Baseline host IPv4 forwarding0 блокируется **до kernel writes**: переключение ip_forward меняет all/default/interface настройки и NIC LRO. Сохранение этих побочных изменений ещё не реализовано; bootstrap не включает forwarding скрытым sysctl. Для baseline1 closed plan сохраняет unrelated forwarding policy. Cores не запускаются, unprivileged service/boot order/recovery ещё не приняты. Current semantic kernel guard result, если operator path проходит, относится к измеренному ruleset/topology; universal native/core/client/ready acceptance остаётся false. Operator runbook: network-stand-runbook.md; ADR-0025.
